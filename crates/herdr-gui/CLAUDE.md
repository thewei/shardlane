# crates/herdr-gui/

> L2 | Parent: ../../CLAUDE.md

The main Shardlane crate (bin `shardlane`). The macOS GPUI client shell + Herdr socket projection + hosted Herdr TUI-only terminal presentation. The old Embedded per-Pane terminal path has been removed from the current working tree. Multi-instance model (2026-09, no registry): a workspace IS a Herdr instance, enumerated live from `herdr session list`; one workspace displayed per window, each window hosting its bound instance's `herdr` child/PTY + private libghostty-vt model + GPUI presentation. One TUI child per instance process-wide (`TuiManagerRegistry`, shared with Remote/mobile viewers; idle children reaped). At most one visible, short-lived auxiliary tool child/PTY per window (currently Lazygit), following the focused Tab's cwd; it is not a second Herdr runtime.

Member inventory:

- `main.rs`: the application shell and ShardlaneApp state machine root — type definitions, `new()`, the Render impl, and the lifecycle restore loop; the method surface is split into shell_* shard modules (inherent impl shards, `use super::*` + `pub(super)`); trailing free helpers and `#[cfg(test)] mod *_tests` remain here. `ConnectionStatus` also carries the structured `UpgradeBlocked(UpgradeGate)` protocol-gate state (M07 #7): `UpgradeGate::blocks` is the one testable 19/20-style boundary, and `ConnectionStatus::from_connection_error` is the single bind/refresh error → state mapping (IncompatibleProtocol lifts into the gate; everything else stays Offline).
- `shell_input.rs`: the terminal input pipeline (IME/key encoding/paste/clipboard/ordered input queue and dispatch), including the explicit `ESC` fallback for legacy Alt with empty encoding.
- `shell_scroll_search.rs`: the terminal local scroll state machine + ⌘F search/highlight/cycle + client search entries.
- `shell_terminal_stream.rs`: the terminal stream lifecycle (frame ingestion/geometry sync/deep-history/visible pane terminal management/reconnect backoff).
- `shell_navigation.rs`: navigation and event projection (workspace/tab/pane focus RPCs, Herdr event subscription, status patch application, status bar snapshot).
- `shell_panes.rs`: the pane operation surface (split/zoom/resize/swap/close/move, process info, agent claim/deny).
- `shell_projects.rs`: project/tab management (create/close/move/pin, sidebar history loading, the new_agent entry).
- `shell_settings.rs`: settings persistence and window preferences (config read/write/reload/font size/always-on-top), plus parking while Settings is open and restoring the Lazygit auxiliary session when the visible right panel returns.
- `providers_view.rs`: Settings → Providers list/detail and History Sources actions; consumes only background availability/integration/source/index snapshots, and config changes rebuild the single HistoryAdapterRoster via ApplicationConfig.
- `shell_theme.rs`: unified App + Herdr theme switching actions and terminal render settings application; Settings and the Main Menu must both land on `theme::THEME_PRESETS` — never maintain a second Terminal theme mapping table.
- `shell_overlays.rs`: overlay and secondary-surface toggles (help/about/picker/settings/mobile/agents/services).
- `shell_render.rs`: the shell chrome render tree (client_shell/sidebar/search bar/overlay assembly); `upgrade_gate_view` (M07 #7) renders the protocol-upgrade card as a window-body branch when the handshake returns IncompatibleProtocol — same inline-recovery skeleton as the TUI failure view, retry button rides the existing Refresh/reconnect flow, and Settings/History stay reachable above the gate.
- `shell_pane_layout_render.rs`: multi-pane layout rendering (grid/resizable nesting/leaf rendering).
- `herdr.rs`: the Herdr socket client and protocol wrappers (all workspace/tab/pane/agent methods, event subscription, the focus family) and socket path resolution (HERDR_SOCKET_PATH/HERDR_SESSION).
- `terminal_stream.rs`: the PTY transport layer of the primary hosted Herdr TUI: child/PTY, ordered writer thread, event-driven shared-session fan-out, bounded viewer frame queue (slow drains apply backpressure), coalesced PTY reader wake, input type boundary, budgeted VT ingestion, and resize/controlling-TTY lifecycle; the Lazygit auxiliary reuses its `ManagedTerminal::host_process`/encoding infrastructure but owns an independent session. Never restore the `terminal session control --takeover` Embedded per-Pane transport; the hosted PTY must give the child a real controlling TTY.
- `terminal_trace.rs`: the hosted Terminal latency observability seam; when `SHARDLANE_TERMINAL_TRACE=1`, records input→PTY→VT→frame→paint phases with a unified monotonic microsecond clock/packet sequence numbers, disabled by default and never recording user text content.
- **Current — Herdr TUI-only:** `herdr_tui.rs` + `shell_tui.rs` host one primary `herdr` child/PTY and crop its native chrome (Tab bar included) via `TuiChromeProjection`: the Pane rectangle from `pane.layout` probes defines the painted projection while the Ghostty model keeps the RAW grid, and PTY resize/mouse/selection/compensated winsize all flow through the projection; Sidebar/Search/History/New Agent navigation routes through protocol focus operations into that same hosted surface. A visible Right Panel may additionally host at most one ephemeral Lazygit child/PTY, bound to the active Project's Git root and stopped on hide/close/switch; it is an auxiliary presentation, never a second Herdr runtime or terminal slot. The system user's `~/.config/herdr/config.toml` (or an explicit `HERDR_CONFIG_PATH`) is the single source of truth for Herdr configuration; Settings edits that file through the shardlane-host `write_user_config_atomic` seam (validate + atomic install, one writer, temp cleaned on every failure path), applies `server.reload_config` afterwards — a failed reload is a degraded success surfaced as the Herdr TUI card's inline red notice (`herdr_config_notice`; a rejected write leaves the file untouched and the notice names the CLI diagnosis) — and generates no `herdr-tui-config.toml` derived mirror. The hosted PTY's Drop must signal synchronously and reap asynchronously. Do not restore Embedded, an External Terminal.app mode, a second Terminal palette, or a second user config.
- `ghostty.rs` (module root → `ghostty/`): the vendored libghostty-vt VT semantics, input encoding, and CPU-side `TerminalFrame` projection (the underlying authority of the hosted TUI's private model; **not** the Ghostty App's Metal renderer). Frame reuse is gated on RAW cell-row signatures and bounded, exact OSC-8 semantic stream equivalence; a projected frame must never be treated as the raw grid baseline. Submodules: ffi (one set of extern "C"+repr(C) structs), terminal (model/writes/BEL scanning), frame (frame extraction), types, encode (key/mouse/focus/paste encoding), selection, alt_screen_and_bell (with #[ignore] perf_* microbenchmarks), scrollback_projection, input, bell, tests.
- `terminal_view.rs`: the hosted Herdr TUI's GPUI presentation bridge. Every visible row is an independent `TerminalRowPane` cached entity; ordinary continuous input rebuilds only rows whose RAW signature changed, and cursor blink/style invalidates only the row that actually owns the cursor. Only global visual changes (theme/font/selection) trigger a full row sync; it owns no runtime scrollback.
- `terminal_interact.rs`: the hosted Herdr TUI's pointer/wheel interaction (Ghostty mouse encoding, precise trackpad row accumulation, alt-screen translation, selection and BEL feedback decisions).
- `terminal_search.rs`: ⌘F scrollback search UI state (row + column range projection).
- `sidebar.rs` (module root → `sidebar/`): the only Sidebar. Submodules: shell (assembly), projection (projection), rows/tree_rows/pane_rows/service_rows (row families; service_rows includes the Agents section's history session fill rows "top up to 10 by most recent update + a fixed trailing View more history sessions row" and the one-shot script exclusion in the Services filter), section_layout. The whole Activity surface was deleted (2026-08-29: titlebar bell + Sidebar routing + the three activity/ shards + receipts persistence).
- `agent_panel.rs`: the Header Agent overview panel — one process-wide Agent directory (`ShellSharedRuntime.agent_directory`, keyed by pane_id, pushed by each window from `notify_status_bar`) aggregated across every bound instance, surfaced as a Popover around the Header's agent summary chip (filter tabs, default Working; row click jumps via the FocusIntent seam, cross-window rows route through the window registry; review-pending rows carry an inline "Mark reviewed"). It also owns `sync_agent_directory_into` (pure merge/prune) and the client-owned unread/review markers flow into it. Presentation projection only: Herdr stays the Agent lifecycle authority; nothing here drives runtime behavior.
- `header_view.rs`: the top bar surface. Movement-revealed chrome (2026-09-19): the content row (buttons/breadcrumbs/indicators) fades 0⇄1 (150ms ease-in-out `HeaderFade` tween, advanced by Render::render like the panel slides) as pointer moves land inside vs. outside the titlebar strip, which stays draggable; the flip is driven by a Capture-phase window mouse-move listener registered from a zero-size `canvas()` paint callback in the header (`on_mouse_event` asserts the Paint phase while view render runs in Prepaint, and element hover listeners get swallowed by the hosted TUI's mouse handling — the chrome stayed revealed while the pointer rested in the TUI). Back/forward navigation buttons were removed with their stack machinery (same date) — do not reintroduce a second navigation-history path.
- `right_panel*.rs`: right panel (Files/Lazygit/Browser/Webview) state and rendering; `right_panel/lazygit.rs` manages auxiliary CLI detection, Git-root resolution, the overlay, and the hosted PTY session, while `lazygit_view.rs` only handles the status card and terminal presentation.
- `workspace_model.rs`: the Project projection (ProjectIndex builder + `VisibleSidebarProject`) derived from the bound Herdr instance's runtime state and Script metadata; the Sidebar Projects section, New Agent composer, right panel, steering, and History session resolution all share it. The legacy client-side Workspace grouping machinery (`workspace_management.rs` and its `workspace_management/` submodules management/restore/config/dialogs/tests, the `config.workspaces` registry, path overrides/last-seen/dormant tracking, the project auto-restore policy, and the sidebar/status-bar/search client-workspace switchers) is deleted (2026-09-01 multi-instance cleanup); `prune_stale_pinned_tabs` survives in `shell_projects.rs`.
- `search_model.rs` / `search_view.rs`: Global Search.
- `history.rs` (module root → `history/`): the read-only catalog projection of Agent conversation history (the UI consumption layer of the shardlane-history crate). Submodules: state (type family/watcher), transcript_view (card-stream rendering)/page_view (master-detail)/sidebar_view (list), browsing (navigation), resume (Continue orchestration), transcript_source (loading), export (Markdown export), formatting, windowing; cross-domain integration tests stay at the root.
- `scripts.rs` (module root → `scripts/`): the Scripts semantic surface; the script monitor (probing/service discovery) carries adaptive backoff and a scan wall-clock budget. Submodules: model (data/persistence, tasks.json→scripts.json with alias migration), observe (observation state machine), ports (lsof parsing), launch (launch orchestration), discovery (discovery cadence), monitor (monitoring loop), editor (editor UI), control (lifecycle control).
- `new_agent.rs` (module root → `new_agent/`): the New Agent surface. Submodules: model (state), launch (launch orchestration), branch (branch decision), page (form page), surface (surface assembly), recent_history (the recent-session preview under the headline: latest 5 by last update for the selected Project via history's recent_history_sessions_for_project, plus a trailing "More history records" row that opens the History surface with the same exact project-path filter; session clicks reuse open_history_session_from_search — one behavior path with the History surface), reference (pure functions for @ file/slash-command triggering and dialect encoding), reference_index (project file index + claude/codex/pi skill catalog scanning), reference_provider (gpui-component completion menu mounting).
- `chat/` (module root → `src/chat/CLAUDE.md`): the Chat semantic sidecar of the same Herdr Agent (state domain + GUI domain; member map inside). Never a second session authority, never a provider-process launcher; prompts go only through the Host submit_conversation_prompt transaction. Approval chips (#2, 2026-09-19) render Codex approval requests decoded from live facts, guard every key replay against the RAW TUI grid text signature (mismatch → Stale, zero keys sent), replay via the existing PTY input seam (queue_terminal_text → TUI_TARGET), and confirm Done by frame-hash change (3s timeout → Unknown).
- `ssh_bridge.rs`: SSH unix-socket forwarding for remote machines (`ssh -N -L`), probed with a herdr ping; bridge children are app-owned and detached.
- `settings.rs` / `settings_view.rs`: the configuration model (~/.shardlane/config.json atomic persistence) and the settings page presentation layer. The normal Terminal is always the Hosted Herdr TUI with no surface-mode selector. Appearance exposes only the 17 combined App + Herdr official theme presets of `theme::THEME_PRESETS`; the Terminal card no longer has a separate theme picker. The Herdr TUI card renders the `herdr_config_notice` failure note inline in red below the card while its controls keep the on-disk truth. The Appearance page also hosts the Language card (`settings::Language`); the entire Settings surface (all 11 section pages, including Providers/Browser/Shortcuts/Mobile sub-views) is served through `i18n::t()`/`t_with()`.
- `i18n.rs` + `locales/`: the native-shell i18n seam on `rust-i18n` 3.1.5 (the same backend gpui-component uses, so one process-global locale covers both). The `rust_i18n::i18n!("crates/herdr-gui/locales", fallback = "en")` embedding stays at the main.rs crate root (`t!` resolves crate-root items); five locales ship in lockstep (en default/fallback, zh-CN, zh-TW, ja, ko — every key lands in all sibling files atomically, enforced by the `locale_files_share_one_key_set` test); `t()`/`t_with()` return `SharedString` (zero-alloc for static translations) and debug-assert missing keys; `t_dyn(key)` serves runtime-composed keys (shortcut registry labels via `shortcuts::label_key`). Language switching flows through `settings::Language` (lenient config deserialization, unknown → En) → `apply_language` at startup (main.rs), from the Settings card (settings_view.rs), and on external config reload via `ConfigDiff::language` (shell_settings.rs). Remaining non-Settings surfaces migrate to `t()` batch by batch (all five locales in the same change); never a second translation path or a runtime loader.
- `update_check.rs`: the client-owned auto update check — fetches the release workflow's latest.json manifest via the releases/latest/download permalink (curl, bounded timeout, `SHARDLANE_UPDATE_MANIFEST_URL` override), compares against CARGO_PKG_VERSION, carries an optional platforms map (keys darwin-arm64/darwin-x86_64/linux-x86_64/windows-x86_64, shared with the site and the release workflow) selected by `platform_key()` with legacy fallback to the flat top-level url, stores the result for the Settings -> Behavior card, and fires the native notification once per new version. The scheduler loop lives in main.rs and re-reads the on-disk `settings::UpdatesConfig` toggle/interval every cycle.
- `update_install.rs`: the client-owned staged update install — downloads the release ZIP (curl, single-flight, file-size progress against the HEAD content-length), verifies SHA-256 against the release .sha256 asset (shasum), extracts with ditto into ~/.shardlane/updates/<version>, and on "Update and Restart" swaps the running bundle (backup rename, staged bundle in place, rollback on any failure, relaunch via `open`; the startup hook clears the backup and staging). Staged install is explicitly macOS-only (`can_install()` gates on target OS plus the .app ancestor); Linux/Windows builds get the platform-matched release asset link (Settings card) instead of an in-place swap. The main.rs scheduler auto-downloads when `settings::UpdatesConfig::auto_download` is on.
- `theme.rs`: Shardlane chrome tokens + 17 combined theme presets. Each `ThemePreset` explicitly carries `appearance`, the App `scheme`, and the exact `herdr_theme`; Hosted Terminal colors themselves are owned only by the Herdr official theme/frame.
- `status_bar.rs`: the macOS Menu Bar Extra (NSStatusItem) — snapshot-driven menu (projects/agents/quick actions). The icon title carries only Agent counts — blocked ⚠️ / review-pending ✅ / working ⚡, ordered by urgency — and never usage/token facts (the #3 usage badge was removed 2026-09-19; provider usage windows remain a host-side `agent_usage` fact for `agent_insight`, not a status-bar concern). The Agents menu groups by Needs Attention / Ready for Review / Working / Idle; review-pending comes from the client-owned `agent_review_pending` markers (cleared by explicit review, a new working turn, or release), so a reviewed agent leaves the count immediately. Every agent row jumps through the shared FocusAgent channel.
 - `browser_profile.rs` / `browser_profile_view.rs`: the Browser Profile domain (config model — including the `browser.preview_discovery_enabled` opt-in for omnibox loopback suggestions, default off, surfaced as a Settings toggle card — + Settings management actions New/Default/Delete/Clear).
- `shortcuts.rs` / `shortcuts_view.rs`: the Shortcut Registry (stable Action IDs, macOS/Linux/Windows platform default profiles, user overrides/conflicts; resolved_bindings drives cx.bind_keys; the key-swallowing decision derives from the registry).
- `status.rs`: the single source of attention levels/predicates (attention_for_raw_status feeds Sidebar row glyphs; attention_for_script/attention_for_agent were removed with the Activity panel; operational_summary is shared). Also owns `classify_agent_transition` — the one (previous, next) status-transition classifier feeding the client unread/review markers, Sidebar display, and notifications.
- `agent_cli.rs`: host Agent CLI discovery/validation; the AgentId→Herdr protocol short id mapping (`herdr_agent_id`).
- `macos_window.rs`: AppKit window preferences (opacity/always-on-top/appearance).
- `macos_window.rs` visibility: `set_visible` (orderOut/makeKeyAndOrderFront) implements the macOS close contract — the traffic light (via `on_window_should_close`) and `app.hide-window` (Cmd+W) HIDE the single window instead of destroying it, and the Dock `on_reopen` path reveals the SAME window, so a hide/show cycle never rebuilds shell state from persistence.
- `input.rs` / `interaction.rs` / `pane_layout.rs` / `rename.rs` / `notifications.rs` / `assets.rs` / `help.rs` / `git_status.rs` / `composer_chip.rs` / `ui_metrics.rs`: input routing, interaction gestures, layout math, rename, notifications (incl. dock attention), lag diagnostics, assets, help, git status, the composer chip, and UI metrics.
