# Shardlane native app source
> L2 | Parent: ../../../CLAUDE.md

Members:
- `main.rs` — native window/root, actions, navigation orchestration, cached shell entities, and shell composition.
- `assets.rs` — centralized GPUI AssetSource for embedded chrome SVGs and Agent brand resources.
- `sidebar.rs` — the single canonical Shardlane Sidebar; the active Shardlane Workspace filters Projects, each Project projects a Herdr runtime workspace with live Tabs/Panes and matching historical Conversations, and global Agent/Script projections remain scoped to the active Workspace.
- `scripts.rs` — Script semantic registry, native creation/editing/lifecycle orchestration, process/port projection, app-owned monitoring, and read-only detection of unmanaged Herdr Pane services with listening ports; Task commands/processes remain Herdr-owned.
- `history.rs` — native History surface and Sidebar metadata bootstrap, full-width one-message-per-row transcript rendering (user bubble / flat assistant / collapsible tool cluster / fixed detail header, hover copy + right-click Copy message), scroll-edge lazy/infinite paging with a bounded sliding window opening at the latest page, cancellable transcript/cache jobs, one ApplicationConfig-backed HistoryAdapterRoster generation shared by scan/watch/detail/export/live binding, and Herdr-only Continue orchestration.
- `interaction.rs` — shared keyboard/focus semantics: `shardlane_interactive` (ordinary clickable controls) and `shardlane_roving_row` + `RovingList` (list roving focus: rows are not Tab stops, the container is the sole stop, ↑/↓/Enter/Esc navigation); individual surfaces keep their own visual layout/state styling.
- `ui_metrics.rs` — intentionally small shared presentation contracts for cross-view insets, row sizes, dialog spacing, and interaction-state strengths; optical/component-specific values stay local.
- `ui/` — the home of Shardlane's shared UI components: `controls.rs` form control family (ControlSurface injected colors + Toggle/Segmented/ControlMenu dumb components), consumed by settings_view and scripts; see ui/CLAUDE.md.
- `workspace_management.rs` — Shardlane-owned Workspace membership, ordering, color, active selection, and Project assignment persisted through application config; never runtime ownership.
- `workspace_model.rs` — disposable Project projection/index mapping Herdr runtime workspaces to Shardlane Project identity and stable project paths; the sidebar Projects ordering truth is the active Workspace's `project_paths` config order (settings-page drag and sidebar drag write the same source), with runtime-only Projects trailing in Herdr runtime order.
- `agent_cli.rs` — host-side Agent executable discovery/project validation for resume; no runtime ownership.
- `mobile_view.rs` — Settings → Mobile secondary surface: Remote toggle/listener status, Port input (`ensure_mobile_port_input`/`commit_mobile_port`, Enter/Blur commits restart the listener), pairing QR, live online clients, and token copy/rotation; the remote service lifecycle belongs to `shell_settings.rs`.
- `font_catalog.rs` — the host monospace font discovery layer: core-text CTFontCollection + kCTFontMonoSpaceTrait filtering with an in-process OnceLock cache (measured ≈100ms on first call); the data source for settings_view's Font family menu; part of the host discovery layer alongside agent_cli.rs.
- `git_status.rs` — header read-only project git observation: pure numstat/ahead-behind parsing (testable) + 12s freshness snapshot collection; consumed by header_view's ±pill and Info popover, zero work-tree writes.
- `composer_chip.rs` — a single silent chip implementing gpui-component's open DropdownMenu trait (icon+label with no caret segment, 5% overlay hover, and a bare inline mode); shared by new_agent's four selector kinds.
- `rename.rs` — native Project/Tab/Pane rename Dialog/Input surface; Project rename submits the real Herdr workspace rename intent.
- `new_agent.rs` — the New Agent landing page: a sentence title (What should we do in {Project}? with a dashed inline picker) vertically centered in the remaining space, with the composer card sunk to the bottom (720/r13/py10, attachments pinned on top, 14px bare field, inverted circular send button, branch context row under the card), Plan/Build dropdown modes, a git branch snapshot, and attachment/submit orchestration; Agent processes/PTY/Tabs belong to Herdr.
- `theme.rs` — Shardlane palettes and gpui-component semantic theme mapping.
- `settings_view.rs` — the Settings page presentation layer (settings_page + section title/control row helpers); the Theme page picks light/dark first (Light/Dark/Auto mode cards) and then that appearance's Herdr official theme card, with Auto showing both groups and both choices; Herdr's non-theme settings merged into the Terminal page's Herdr TUI card and the Herdr section was deleted; config read/write and actions remain owned by main.rs.
- `providers_view.rs` — Settings → Providers list/Provider detail and History Sources management; availability, Herdr integration health, source existence, and History index metadata are all driven by background caches, and source writes go into ApplicationConfig and rebuild the same HistoryAdapterRoster generation.
- `header_view.rs` — the Header/titlebar presentation layer (window_header: breadcrumbs, compact fallback, operation indicators); consumed by the ui.crepus root template.
- `settings.rs` — Shardlane local appearance/interaction/Lazygit preference persistence (`ApplicationConfig`, including the auxiliary CLI path and overlay/startup/interface settings plus user-owned HistorySourcePolicy; the history catalog remains disposable).
- `herdr.rs` — Herdr socket API wrappers; global Workspace/Tab/Agent metadata projection, typed Agent start/prompt/read/wait/send-keys contracts, the UI-independent `shardlane-host` AgentRuntime adapter, and layout runtime projection. Navigation selection belongs to the client: no workspace/tab/pane focus wrappers are provided; `layout.focused_pane_id` serves only as a zoom runtime-fact fallback and never drives navigation.
- `search_model.rs` — the Global Search/picker domain model layer: query parsing (hash prefixes/filter words), result item and scope types, `ClientSearchDelegate` (the full gpui-component ListDelegate chain), and history→search adapters; overlay presentation belongs to `search_view.rs`, while projection building (client_search_items) and navigation actions belong to `main.rs`.
- `terminal_interact.rs` — the complete home of the terminal interaction domain: pixel→cell hit testing, cell/word/line selection state machines (Ghostty semantic selection ABI), mouse/wheel encoded reporting (the try_report family), wheel row conversion, and SelectionGeometry interaction geometry; the first child-row event of a precise wheel gesture immediately owns it, while rendering/polling remain in `main.rs`.
- `pane_layout.rs` — split-pane rectangle layout math (after TUI-only convergence only directional navigation neighbor computation remains: `neighbor_pane_in_direction`).
- `terminal_stream.rs` — the transport layer of the primary Hosted Herdr TUI: one local `herdr` child + one PTY + one local Ghostty model; shared viewer fan-out is event-driven with no fixed 16ms output polling layered on top, viewer frame handoff uses a bounded queue with backpressure against slow GPUI drains, and input/the PTY writer stay ordered and serial with coalescing boundaries marked per event type; `ManagedTerminal::host_process` is the spawn/controlling-TTY foundation shared by the primary and the Lazygit auxiliary (their session states are independent and the auxiliary never occupies the Herdr global terminal slot); it carries the host terminal emulator's dynamic color semantics (model OSC 10/11 seed + child query answers, colors derived from the Herdr theme).
- `ghostty.rs` — vendored libghostty-vt semantics/FFI (terminal model, mouse/paste/focus/key encoders, OSC 10/11 dynamic-color seed/query-answer helpers) and terminal frame extraction with authoritative grid-column/span projection; `frame_reusing` adds a frame-level RAW-bitfield signature fast path plus exact bounded OSC-8 stream equivalence (no heuristic cache) on top of row-level hyperlink reuse, and surfaces the row-level verdict to consumers as `TerminalFramePlan` (`take_last_frame_plan`). Hosted TUI projection keeps the raw frame separate from the visible chrome-projected frame.
- `terminal_view.rs` — GPUI-font-metric terminal geometry plus fixed-cell painting, with `TerminalFramePlan`-limited row re-sync (`plan_sync_row_targets`) falling back to the full deep pass whenever the plan proves nothing, cursor/hitboxes, selection, scrollbar, and link presentation. The row grid height is fixed to rows × cell_height (`cached_view`'s `flex_1` wrapper would evenly divide a size_full container's height across rows, leaving a ~0.7px bottom seam per row → periodic 1px gaps in the Herdr scrollbar ▕/▐ geometry overlay); Block Elements render as cell-geometry overlays, with continuity evidence and regression: `scripts/scrollbar-continuity-ab.sh` + `scrollbar_block_cells_get_geometric_overlays_through_real_ghostty`.
- `input.rs` — keyboard/input translation helpers: resolved app-shortcut swallowing, GPUI→Ghostty physical-key mapping (the terminal encoding boundary includes macOS shifted US symbol normalization; GUI shortcut/script names keep GPUI's raw key), and the explicit `ESC` fallback byte for legacy Option/Alt printables.
- `help.rs` — native Help overlay content.
- `macos_window.rs` — the AppKit window-level adaptation layer: opacity/always-on-top/appearance (forced dark) applied via raw-window-handle to the NSView; macOS target only.
- `notifications.rs` — macOS UserNotifications presentation adapter: only delivers Herdr's authoritative Agent lifecycle state transitions as system notifications (unfocus gating + dock attention) and owns no lifecycle; notifications carrying a pane_id route clicks back to the GUI to jump to that pane via the static delegate channel (the full P2-2 loop).
- `steering.rs` — steering domain leftovers (draft pruning and agent-pane detection pure functions); composer rendering was deleted with the Embedded per-Pane renderer, and after TUI-only convergence this input surface awaits a Herdr TUI-side solution.
- `right_panel.rs` — the main collapsible right panel container: Surface Tab management, Tab switch/close/add menus, the Chooser onboarding card, and the file/Lazygit/browser main-view rendering and interaction.
- `right_panel_files.rs` — workspace file directory tree traversal (ignoring .git/node_modules/target and other build artifacts), recursive collapse/expand, icon mapping for 100+ language extensions and special files, and a read-only file content viewer.
- `right_panel/lazygit.rs` — Lazygit auxiliary CLI detection/version gating, Git-root resolution, the Shardlane overlay, an independent `ManagedTerminal` session, and lifecycle routing.
- `right_panel/lazygit_view.rs` — the Lazygit status card, error/restart entries, and `TerminalPane` hosted frame presentation.
- `status_bar.rs` — the native integration layer for the macOS top status bar (Menu Bar Extra / NSStatusItem): live projection of workspace/project/Agent status (working count / blocked-awaiting count), with multi-level submenus to switch workspaces, projects, and the Agent panel plus quick actions.
- `right_panel_browser.rs` — embedded local web/documentation preview and Omnibox address parsing: smart scheme guessing for local ports/IPs/domains and one-click open in the system default browser.
- `shell_input.rs` — the terminal input pipeline: IME/key encoding/paste/clipboard/ordered input queue and dispatch; the swallow table and overlay occlusion guards return first, script hotkeys next, and the input-surface (steering composer/⌘F search) focus guard intercepts last (keys never enter the terminal); legacy Alt with empty encoding gets an `ESC` fallback at the hosted PTY boundary.
- `shell_navigation.rs` — navigation and event projection: **FocusIntent seam** (`FocusIntent` + `apply_focus_intent` + `drive_tui_focus_chain` + `complete_navigation_after_authoritative_selection`, the unified landing for Sidebar/Search/History/New Agent/Activity/notification/status), Herdr global event subscription, navigation/status patch application and memory table pruning; the ⌘1..⌘5 workspace-switch macro family.
- `shell_render.rs` — the shell chrome render tree: client_shell/sidebar/search bar/overlay assembly; normal content = `tui_surface_view` (the sole hosted Herdr TUI surface, with the failure recovery placeholder and IME overlay), and the Help overlay hangs off the content area root.
- `shell_overlays.rs` — overlay and secondary-surface toggles: help/about/picker/settings/mobile/agents/services.
- `shell_panes.rs` — the pane operation surface: split/zoom/resize/swap/close/move plus process info and agent claiming, all non-navigation RPCs sharing the `run_pane_rpc` scaffold (background projection + UI-thread apply + Connected/notify_sidebar/notify on success, Offline+notify on failure; no navigation token/loading lifecycle); includes the focus/resize direction-key macro family.
- `shell_projects.rs` — project/tab management: create/close/pin, Tab drag display-order→authoritative-order conversion with Herdr tab.move, Project drag ordering (writing the active workspace's config project_paths), and sidebar history loading.
- `shell_scroll_search.rs` — terminal scrolling and find: local scroll state machine + ⌘F search/highlight/cycle + client search entries.
- `shell_settings.rs` — settings persistence and window preferences: config read/write/reload/font size/always-on-top; parking while Settings is open and restoring the Lazygit auxiliary session when the visible right panel returns.
- `shell_terminal_stream.rs` — the hosted terminal lifecycle: frame ingestion (deep-compare fast paths replaced by the exact `TerminalFramePlan` row-level extraction plan where proven)/geometry sync (including chrome-compensated PTY winsize)/`attach_focused_terminal` = ensure the host is alive.
- `shell_theme.rs` — theme and terminal render settings: palette sync and the sync_terminal_theme large state machine.
- `search_view.rs` — the Global Search/picker overlay presentation layer; the domain model lives in `search_model.rs`, and projection building/navigation actions belong to `main.rs`.
- `main_tests.rs` — herdr-gui's unit test pin set: guard predicates/deep-history budget relations/steering detection/notification transition semantics and other pure-logic regressions.

Rules:
- Shardlane is the client; Herdr runtime authority stays in `herdr.rs` and the real Herdr protocol/CLI names remain unchanged.
- External Agent history parsing/catalog/resume command semantics stay in the `shardlane-history` crate; host executable discovery stays in `agent_cli.rs`; `history.rs` executes continuation through Herdr only.
- `sidebar.rs` is the only Sidebar implementation. A Shardlane Workspace is a client-owned grouping above Projects; a Project is the user-facing projection of a Herdr runtime workspace. Keep the top-level History library entry, matching History Conversations under Projects, and keep Scripts/Agents as scoped projections rather than a second runtime. Deduplicate live vs historical presentation only by stable Agent session identity; never delete History data or match by title.
- Until Herdr exposes protocol-native Script identity, `scripts.rs` may persist Shardlane-owned Script definitions/correlation IDs under `~/.shardlane/`; Script semantic Project identity is the stable `project_path`, while `workspace_id`/`tab_id`/`pane_id` are disposable runtime correlation only. All Script Tab/Pane/PTY/process creation, input, focus, and termination must still route through Herdr. Prefer a dedicated Script Pane split inside an existing Project Tab; Stop/Restart/one-shot completion close only that Script Pane and must not close unrelated sibling Panes or the containing Tab; Delete removes the Script definition only and leaves its Pane open as an ordinary Pane. Ordinary Herdr Panes with foreground listening services may be projected read-only into Services, but that projection is disposable/non-persisted and must never gain stop/restart/delete ownership. Do not add a Script daemon.
- Sidebar assets use `assets.rs` logical paths; do not add ad-hoc filesystem asset loading. Every Provider with a verified redistributable brand asset must resolve it via both its history slug and Herdr protocol label; a Preview Provider without confirmed licensing (currently Qoder) must use the neutral Bot fallback and stay covered by the asset regression.
- Terminal semantics stay in `ghostty.rs`; the normal surface is the singleton hosted Herdr TUI (`shell_tui.rs` lifecycle + `terminal_stream.rs` PTY-only transport). There is no per-Pane controller, no local viewport/scrollbar/scrollback-search, and no `pane.send_keys` fallback anymore — named keys and ctrl/alt chords encode through `ghostty.rs`'s `ghostty_key_encoder` and dispatch as ordered PTY bytes. Keyboard priority is one chain (focused control → resolved Shortcut Registry → Script hotkey → hosted TUI); never add a second hand-maintained swallow list. Ordinary right click is the native Copy/Paste/Select All menu with Right input withheld from the PTY.
- Split modules only when a stable ownership seam exists; do not split merely to reduce line count.
