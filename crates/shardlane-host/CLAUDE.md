# Shardlane Host contracts
> L2 | Parent: ../../CLAUDE.md

Members:
- `Cargo.toml` — dependency boundary for the UI-independent Host contract crate (including `shardlane-history`: consumed only for `agent_integrations`'s AgentId exhaustive invariant, with no reverse dependency cycle).
- `src/lib.rs` — public Host contract surface.
- `src/agent_integrations/` — the **install/health layer** for Agent Provider → Herdr integration (coverage batches A/C complete and live-verified; the Gemini integration was deprecated and removed, the Kiro/DSH bridges are postponed until their CLIs are installable; Qoder History is integrated but its Herdr hooks/session bridge is explicitly Deferred): `registry.rs` enumerates all 15/15 of `AgentId::ALL` with explicit strategies (wildcard-free match, so a new Provider fails to compile here), `herdr_official.rs` idempotent ensure/audit of the official integration (`herdr integration status/install`; current → zero writes; unlanded bridge strategies are explicitly Deferred), `managed_file.rs` atomic managed-file primitives (the file name is the owned entry), `providers/command_code.rs` + `assets/` the Command Code managed Mod (natural detection / working / idle / exit-release live-verified; session projection is an upstream Herdr gap), `health.rs` read-only IntegrationHealth (no working/idle/blocked — that is Herdr runtime data). **Not a second Agent runtime state**; the GUI launch seam (new_agent/launch, history/resume) calls `ensure_agent_integration` before raising a Provider.
- `src/ids.rs` — opaque client identifiers plus the versioned ProjectId ↔ existing Project locator bridge; never a second Project store.
- `src/conversations.rs` — one opaque Live/History Conversation identity bridge, exact Herdr `AgentSessionInfo` source resolution, and provider-neutral bounded item normalization shared by native and remote clients.
- `src/agent_service.rs` — concrete Host Agent query/read/wait/keys service over the runtime SPI, plus the canonical runtime-state → `AgentSummary` projection shared by bootstrap and product callers; it never owns launch policy or client focus.
- `src/conversation_service.rs` — concrete Host Conversation application service for bounded Live/History detail, semantic prompt, and the Host-owned Continue transaction; successful History Continue is fail-closed unless a Live identity is bound. Provider locators remain internal and public identities redact file paths. Live reads route through the shared session manager when attached.
- `src/conversation_queue.rs` — safe Working follow-up queue: exactly one semantic item per live Conversation with full identity capture; delivery runs an exact-target settle wait (never a global watcher), revalidates the occupant, prompts exactly once, retains on Blocked/timeout, fails closed on identity change, and never auto-retries uncertain acceptance.
- `src/conversation_sessions.rs` — Host-owned bounded Live Conversation session manager: one subscribed `LiveSession` per exact source in-process (GUI Chat worker holds `LiveLease` and drives incremental sync; Remote/transient readers get non-destructive `shared_snapshot` so subscriber deltas are never drained; last lease releases the session — no always-on fleet).
- `src/conversation_delivery.rs` — process-shared queued-delivery owner plus atomic-admission Prompt `MutationLedger` and typed Agent `LaunchOperationLedger`; Conversation locks serialize Prompt/Handoff boundaries and terminal/uncertain outcomes replay by logical operation id.
- `src/provider_capabilities.rs` — one provider-product capability projection composed from the History registry, resume support, integration strategy, and caller-supplied environment facts; GUI/Remote must consume it instead of copying provider tables.
- `src/agent_launch.rs` — the one normal Agent launch transaction over Herdr Agent APIs (`agent.start`/`wait`/`prompt`/verified keys): preparation seam (`ProjectPreparation`/`GitWorktreePreparation`), Host startup argv/plan-key/prompt policy, typed failure phases, focus-free runtime creation, exactly-once initial prompt, exact Conversation binding, cleanup matrix. PTY text/Enter is never the Agent launch/prompt transport.
- `src/agent_insight.rs` — bounded AgentSessionInsight projection derived from existing parser facts (live snapshots / History metadata): model, provider-reported tokens, message/turn/tool counts, session duration, freshness/compaction, and typed `InsightPressure` with at most one surfaced signal. No parallel provider parser, no render-path I/O, no token dashboard.
- `src/live_handoff.rs` — native Live Handoff over the shared transfer engine: Working sources run `Handoff after current turn` (exact-target settle wait → occupant revalidation → snapshot), the source Agent is never stopped or mutated, the target launches through the canonical M2 transaction with the briefing as its single initial prompt, and failures are typed (source unresolved / wait failed / identity changed / snapshot / transfer). Structural placement is `NewTab` only; there is no Host FocusTarget.
- `src/history_continuation.rs` — the canonical History continuation planner (AlreadyLive → NativeResume → ContextTransfer → NeedsProjectSelection → Unsupported, read-only before any mutation) and its executor over the M2 launch transaction and M5 transfer engine; AlreadyLive never creates a duplicate Agent, instructions are optional, and the legacy Continue/Fork transaction seam was removed with it.
- `src/context_transfer.rs` — the one lossless Context Transfer engine shared by History cross-Provider Continue and Live Handoff: capture → inline/artifact with accessibility gate → deterministic briefing → canonical M2 launch delivering the briefing exactly once; fails closed on unavailable artifacts with no partial-context fallback.
- `src/agent_titles.rs` — pure deterministic task-title heuristic (no model/network); high-confidence only, provider display name stays the fallback.
- `src/dto.rs` — small serde projections for bootstrap, Workspace/Project/Tab/Pane/Agent/Script/History metadata, bounded Conversation windows, and the Host-owned shared Herdr TUI session summary.
- `src/runtime.rs` — UI-independent runtime SPI used by concrete Host services; carries runtime correlation but no transport/socket ownership.
- `src/services.rs` — narrow Agent request/result contracts and provider-neutral action enums with explicit target IDs; concrete Conversation/Agent implementations live in the focused service modules above.
- `src/herdr.rs` — the Herdr socket client and protocol wrappers (all workspace/tab/pane/agent methods, event subscription, Agent correction report/clear, socket path resolution), herdr/wax CLI discovery, and the Host-owned TUI spawn environment shared by native/Remote (strips nested Pane identity but keeps the user's config/socket); the GUI consumes it through a `pub use` shim.
- `src/shared_tui.rs` — single Host-owned Herdr TUI child/PTY slot with event-driven shared viewer fan-out (plus a bounded frozen startup-replay prefix so late viewer models still observe the child's pre-subscription DECSET mode bursts — SGR mouse reporting, alternate screen), serialized input/resize, a bounded byte-budget input queue that coalesces adjacent compatible packets without dropping order, trace-only writer/read timing, and `Terminating` lifecycle released only after the OS child wait/reap signal.
- `src/diagnostics.rs` — the lag log and remote diagnostics share one channel (`lag_log` pub); writes `/tmp/shardlane-lag.log` by default, and isolated native smokes can point `SHARDLANE_LAG_LOG_PATH` at a separate file.
- `src/project_index.rs` — the ProjectIndex projection (extracted in B3; GUI convenience wrapper).
- `src/workspace_config.rs` — the workspace configuration projection (extracted in B3).

Rules:
- This crate must compile without GPUI, gpui-component, AppKit, HTTP/WebSocket servers, or Relay dependencies.
- Herdr remains runtime authority; concrete adapters may call Herdr but may not duplicate its Workspace/Tab/Pane/Agent/process state.
- Remote-facing IDs are opaque. Project paths may appear as metadata but never as the public Project identifier.
- Service methods use explicit IDs; never infer a remote target from Herdr global focus or the Mac client's current navigation.
- Bootstrap remains bounded metadata and must not contain full History transcripts or terminal scrollback.
- Networking/auth belongs in later Host adapter layers, not in these core DTO/service contracts. The shared TUI process belongs to the Remote adapter, not this crate; this crate only supplies its command/env seam and DTOs.
