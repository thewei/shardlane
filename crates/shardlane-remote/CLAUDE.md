# Shardlane Remote (loopback Remote API)
> L2 | Parent: ../../CLAUDE.md

Members

- `src/lib.rs` — the crate's public surface: re-exports RemoteConfig/ListenerMode/DEFAULT_REMOTE_PORT and the hello_response/spawn_remote_server handle types.
- `src/config.rs` — the `remote` section model of `~/.shardlane/config.json`: the loading layer normalizes a missing or explicit-0 port to `DEFAULT_REMOTE_PORT` (8757); the server binding layer preserves `0=ephemeral` (loopback integration tests only). Token/host_id generation and rotation also live here and never appear in logs.
- `src/server.rs` — the axum server: the single `/api/v2` surface (hello/bootstrap; Herdr workspace/tab/pane control re-homed from the retired `/api/v1` compatibility routes on 2026-09-01; events WebSocket at `/api/v2/events`), `/api/v2` semantic Conversation and Host-owned shared Herdr TUI routes, plus static Mobile Web; every response carries `x-request-id` (D12); handlers share decode_body/run_herdr (D01); `hello_response` declares capabilities; pre-spawn gates (enabled/listener_mode/token).
- `src/conversations.rs` — Remote API v2 semantic Live/History Conversation adapter layer: decode → `shardlane-host::HostConversationService` → encode. Provider resume/workspace/start/readiness policy, live semantic source resolution, and the exactly-once prompt transaction all live in Host (M1 convergence); Continue goes through the Host continuation planner (M6: strategy result + optional instructions + NeedsProjectSelection 409 contract), and success responses must encode the full live identity, failing closed when missing; this file no longer owns any Continue/prompt production policy. History reads share the per-process HistoryCatalog handle (D14).
- `src/auth.rs` — Bearer/WS subprotocol authentication; credentials never enter URL query/localStorage/logs.
- `src/bootstrap.rs` — bootstrap DTO assembly; capabilities aligned with hello (semantic
  Conversation/History are already projected by the v2 service; mobile-side entry gating reads the capability).
- `src/events.rs` — event hub: 1 Herdr subscription socket → broadcast → N WS clients, exiting on the stop signal.
- `src/tui.rs` — one Host-owned shared Herdr TUI session/PTY manager and authenticated byte-stream WebSocket; all clients observe the same global focus/resize semantics, with bounded idle and deterministic shutdown; never creates per-Pane/per-client runtimes; stream viewers register in the shared web-connection registry (D23).
- `src/tui_tests.rs` — isolated deterministic unit tests for shared TUI bounds and stream wire frames; it never launches a runtime.
- `src/tui_input.rs` — typed text/paste/key input decoder and Host-side named-key encoding; preserves the raw WTerm compatibility shape without moving ANSI interpretation into Mobile.
- `src/state.rs` — RemoteState + web connection registry (WS lifecycle drives register/touch/drop for both the events and TUI stream sockets) + the shared HistoryCatalog handle (D14).
- `src/cors.rs` — development origin allowlist; production prefers the Host same-origin.
- `src/error.rs` — the unified error envelope ApiError (the basis for mapping 404/401 etc. in the remote API), echoed in the `x-request-id` response header (D12); the wire-code vocabulary is pinned by test including the reserved `forbidden`/`unsupported_capability` codes (D25);
  `agent_created` additionally carries opaque created-target fields for client reconciliation.
- `src/idempotency.rs` — bounded Remote mutation cache keyed by logical request id/fingerprint; replays stable responses, conflicts on shape reuse, and retains committed `agent_created` outcomes.
- `tests/golden_fixtures.rs` — golden wire-format contracts for hello/bootstrap/agent_output, shared TUI session/input, and semantic Conversation
  (herdr-mobile copies the same fixtures and runs Zod); `UPDATE_FIXTURES=1`
  rewrites them. hello.json is generated by the real `hello_response()`;
  bootstrap.json and the Conversation fixtures pin the Rust→Mobile shape and
  do not represent a full runtime snapshot.
- `tests/loopback_api.rs` — loopback integration tests; depend on `port: 0` ephemeral binding; do not change the server binding layer semantics.

Rules:
- When Herdr goes offline, the external semantic is host_unavailable (`HerdrClient::connect`; it does not start a runtime on the user's behalf).
- The token only travels via Authorization/WS subprotocol; static web resources are Bearer-free, while API/WS always require authentication.
- Configuration normalization (port/listener mode/identity) happens only in the loading layer; the binding layer faithfully uses the given values.
- `herdr_tui` advertises the implemented shared session; runtime/operator and native VT verification remain explicit gates. Semantic navigation remains client-local while explicit TUI actions may mutate Herdr global focus.
